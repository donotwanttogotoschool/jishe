# Prompt: 构建《千载格物》项目的数据处理流水线

你好，AI 助手。我们正在开发一个名为《千载格物：中国古代自然科学的可视化探索》的信息可视化项目。现在，我们需要构建一个健壮、可复现的数据处理流水线。请你扮演一位资深的数据架构师和 ETL 工程师，为我们设计并提供这个流水线的完整方案和关键代码示例。

**项目背景：**

- **主题：** 中国古代自然科学史
- **数据源：** 格式不统一，来源多样，包括：
  1.  公开出版的学术著作（如《中国科学技术史》）的扫描版 PDF 或文本。
  2.  权威网站（如国家博物馆、中科院官网）的 HTML 页面。
  3.  地方志、古籍文献的非结构化文本。
- **最终目标：** 将原始数据处理成结构化的、干净的、相互关联的数据，并存储到 MySQL 数据库中，以供前端可视化和后端 API 调用。

**核心实体类型：**

- **人物 (Person):** 如张衡、李时珍。
- **成就 (Achievement):** 如地动仪、活字印刷。
- **著作 (Work):** 如《本草纲目》、《九章算术》。
- **地点 (Location):** 如长安、洛阳、河南省。
- **年代 (Dynasty/Time):** 如汉代、公元 132 年。

---

**任务要求：**

请为我们规划并实现一个“**五步清洗**”的 ETL (抽取、转换、加载) 流程。请为每一步提供清晰的逻辑描述、推荐的技术栈（以 Python 为主），以及关键步骤的 **Python 代码示例**。

### **第一步：数据抽取 (Extraction)**

1.  **目标：** 从不同的数据源中自动抓取原始数据。
2.  **任务：**
    - 设计一个通用的爬虫框架。
    - 提供一个使用 `requests` 和 `BeautifulSoup` 爬取网页信息的 Python 代码示例。
    - 提供一个使用 `PyPDF2` 或 `pdfplumber` 提取 PDF 文本的 Python 代码示例。

### **第二步：实体识别与标准化 (Entity Recognition & Standardization)**

1.  **目标：** 从非结构化文本中识别出核心实体，并进行标准化处理。
2.  **任务：**
    - 推荐使用的 NLP 库（如 `spaCy` 或 `jieba+LTP`）。
    - 提供一个 Python 代码示例，演示如何从一段文本中识别出“人物”、“地点”、“著作”等实体。
    - 设计一个“标准化词典”的数据结构（例如，用 JSON 文件），用于将“长安”、“京兆”统一映射为“西安市”；将“北宋”、“南宋”统一为“宋朝”。

### **第三步：关系链接与图谱构建 (Relation Linking)**

1.  **目标：** 识别并构建实体之间的关系。
2.  **任务：**
    - 设计关系抽取的规则。例如，识别句式 `[人物] 著有 [著作]` 或 `[成就] 发明于 [年代]`。
    - 提供 Python 代码示例，演示如何基于上一步识别的实体，构建出如 `{'subject': '李时珍', 'relation': '撰写了', 'object': '本草纲目'}` 这样的关系三元组。

### **第四步：消歧、量化与地理编码 (Disambiguation, Quantification & Geocoding)**

1.  **目标：** 解决数据冲突，为数据增加量化指标，并空间化。
2.  **任务：**
    - **消歧 (Disambiguation):** 描述一个简单的消歧算法逻辑，如何通过“年代”和“领域”来区分同名人物（如不同朝代的“李白”）。
    - **量化 (Quantification):** 设计一个简单的“影响力指数”计算逻辑。例如，`影响力 = (提及次数 * 0.5) + (是否为核心成就 * 0.5)`。
    - **地理编码 (Geocoding):** 提供一个调用第三方地理编码 API（如高德地图 API）的 Python 函数示例，将地点名称（如“开封市”）转换为经纬度坐标。

### **第五步：数据加载 (Loading)**

1.  **目标：** 将处理好的结构化数据存入 MySQL 数据库。
2.  **任务：**
    - 设计 MySQL 的数据库表结构（`persons`, `achievements`, `works`, `relations` 等），并提供`CREATE TABLE`的 SQL 语句。
    - 提供一个使用 `SQLAlchemy` 或 `pymysql` 将 Python 中的数据对象（如一个包含人物信息的字典）批量插入到 MySQL 数据库的 Python 代码示例。

请将以上所有内容组织成一个结构清晰的 Markdown 文档，确保逻辑连贯，代码示例实用且带有注释。

# Prompt: 设计并构建《千载格物》项目的“灵枢 AI”智能问答系统

你好，AI 助手。我们正在为《千载格物》项目开发一个名为“灵枢 AI”的智能问答系统。请你扮演一位资深的 AI 架构师和 NLP 工程师，为我们设计一个基于 RAG（检索增强生成）架构的完整方案，并提供关键模块的 Python 代码实现。

**系统目标：**

- **核心功能：** 用户输入自然语言问题，AI 能够基于我们自己的数据库内容，提供准确、深入、有据可查的回答。
- **高级功能：** AI 的回答能驱动前端可视化图表的动态变化（如高亮、筛选）。
- **技术栈（推荐）：**
  - **大语言模型 (LLM):** Kimi (Moonshot AI)
  - **后端框架:** Flask
  - **向量数据库/索引:** FAISS 或 ChromaDB
  - **嵌入模型:** BGE-M3 或任何高效的中文嵌入模型

---

**任务要求：**

请为我们设计一个完整的 RAG 流程，从数据预处理到最终的智能应答。请为每个关键步骤提供逻辑描述和核心的 **Python 代码示例**。

### **第一步：知识库构建与向量化 (Knowledge Base & Vectorization)**

1.  **目标：** 将我们 MySQL 数据库中的结构化数据，处理成适合 RAG 检索的格式，并进行向量化。
2.  **任务：**
    - **文档构建:** 提供一个 Python 函数示例，它能连接到 MySQL，查询数据（例如，查询“张衡”的所有信息，包括他的成就和著作），并将其整合成一段有意义的、信息丰富的文本（Document）。
    - **文本切块 (Chunking):** 描述为何需要以及如何进行文本切块，推荐一个策略（如按段落或固定长度）。
    - **向量化与存储:** 提供 Python 代码示例，演示如何使用一个嵌入模型（如 `bge-large-zh-v1.5`）将文本块转换为向量，并将其与元数据一起存储到向量数据库（以 `FAISS` 或 `ChromaDB` 为例）中。

### **第二步：用户查询理解与多路检索 (Query Understanding & Multi-path Retrieval)**

1.  **目标：** 准确理解用户意图，并从知识库中检索出最相关的“事实”和“可视化指令”。
2.  **任务：**
    - **意图拆解 (Decomposition):** 描述如何将用户问题（如“请介绍宋代最重要的航海技术及其地理分布”）拆解为结构化查询意图（如 `{'dynasty': '宋代', 'domain': '航海技术', 'analysis': '地理分布'}`）。可以假设使用简单的规则或调用 LLM。
    - **向量检索 (Vector Retrieval):** 提供 Python 代码示例，演示如何将用户问题向量化，并在向量数据库中进行相似度搜索，检索出最相关的文本块（上下文）。
    - **可视化元数据检索:** 描述如何根据用户意图，从 MySQL 中检索出与事实相关的“可视化元数据”（如成就对应的地图坐标、图表 ID 等）。这是我们系统的创新点。

### **第三步：智能上下文聚合与 Prompt 工程 (Context Aggregation & Prompt Engineering)**

1.  **目标：** 将检索到的信息智能地组合成一个高质量的 Prompt，以指导 LLM 生成我们期望的回答。
2.  **任务：**

    - **设计一个“双重任务”Prompt 模板。** 这个模板需要非常巧妙，它要包含以下部分：

      - **角色扮演指令：** `你是一个中国古代科技史专家...`
      - **约束指令：** `请严格根据我提供的“上下文”来回答，不要使用任何外部知识...`
      - **事实上下文占位符：** `{retrieved_facts}`
      - **可视化上下文占位符：** `{visualization_metadata}`
      - **回答格式指令：** 要求 LLM 生成两部分内容：1) 给用户的自然语言回答；2) 给前端的可视化指令 JSON。

    - **提供一个将检索到的信息填入此模板的 Python 函数示例。**

### **第四步：LLM 调用与响应解析 (LLM Call & Response Parsing)**

1.  **目标：** 调用 LLM API，并解析返回的结果，分离出给用户的文本和给前端的指令。
2.  **任务：**
    - 提供一个使用 `requests` 或 Kimi 官方 SDK 调用 Moonshot AI API 的 Python 函数示例。
    - **流式响应 (Streaming):** 请特别展示如何实现流式响应，以提升用户体验。
    - 设计一个简单的解析逻辑，用于从 LLM 的完整输出中，准确提取出“自然语言回答”和“可视化 JSON 指令”这两部分。

### **第五步：后端 API 封装 (Flask API Endpoint)**

1.  **目标：** 将整个 RAG 流程封装成一个 Flask API 接口。
2.  **任务：**
    - 提供一个完整的 Flask 应用示例，包含一个 `/api/ask_ling_shu` 的路由。这个接口接收用户问题（POST 请求），执行上述 1-4 步，并以流式响应（`StreamingHttpResponse`）的方式将结果返回给前端。

请确保你的方案完整、可操作，并且代码示例清晰、带有注释，能够直接帮助我们团队快速启动开发工作。
